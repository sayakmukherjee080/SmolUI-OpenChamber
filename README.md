# SmolUI for OpenChamber

Turns agent answers into interactive visuals. The agent writes a `.visual.html`
fragment; SmolUI renders it inside OpenChamber, live, themed, in a sandbox —
and the same file downloads as one standalone page that works offline.

## What you get

- **Prompt box** — ask from the panel itself ("Ask for a chart, a map, a plan…"); the answer streams back as the agent writes it, with a "writing…" state and faster refresh while it works.
- **Rail panel** — every `.visuals/*.visual.html` in the project, newest
  first. Click one to render it in the panel.
- **Message action** — "Open as visualization" on assistant messages that
  name a visual.
- **File editor** — opening a `.visual.html` in Files renders it there and
  refreshes when the agent edits it.
- **Full-screen page** — the same view from the Extension pages menu.
- **Ask buttons** — a visual can put a question in the chat box. SmolUI never
  sends a message on its own.
- **Download** — the skill builds `.visuals/<slug>.html`, one self-contained
  page (fonts and libraries inside, network blocked by CSP). Open it in Files
  and use the built-in Download action.

## Install

1. Settings → Extensions → paste the absolute path of this folder (or the git
   URL) → Add.
2. Approve the two things it asks for: `files` access and the local service.
3. Open the SmolUI panel once. The service installs the `visuals` skill into
   `~/.config/opencode/skills/visuals/` and re-syncs it whenever this
   extension updates. Nothing else to do.

If the service is not approved, the panel shows a toast telling you where to
approve it. The extension works for viewing without it; the agent only gets
the skill once the service ran.

## How it fits together

1. The agent (OpenCode, using the `visuals` skill) writes
   `.visuals/<slug>.visual.html` and builds `.visuals/<slug>.html`.
2. SmolUI reads the fragment and builds the same standalone page in the
   browser, byte-for-byte identical to the skill's Node build (a test proves
   it for all ten golden examples).
3. The page runs in a nested `sandbox="allow-scripts"` frame: no same-origin,
   no network, no popups, no downloads. Only two messages cross back — the
   frame height and an optional ask.

## Permissions

| Asked for | Used for |
| --- | --- |
| `files` | reading the project's `.visuals` folder; stat of the download |
| `prompt` | sending what you type in the panel's prompt box into the open session |
| local service | copying the skill into `~/.config/opencode/skills/visuals/`; runs with your access, talks to nothing |

No network, no `origins`, no integrations. The panel fetches its own package
assets (libraries, fonts payload) from the server that served it.

## If something fails

- A failed render shows a banner with **Retry** — nothing fails silently.
- Assets load over two transports: the package fetch (fast) and, if that is refused, the extension's **local service** reading the package in chunks. The panel's frame token lives about a minute, so this is what keeps a long-open panel rendering new libraries after the token expires.
- The skill-install notice is shown at most once a day, so an unapproved service never nags on every open.

## Develop

```
npm install
npm run build          # syncs skill/, generates the fonts payload, bundles panel/main.js
npm test               # parser, parity vs assemble.mjs, service behaviour
npm run test:browser   # Playwright stub-host harness (npx playwright install chromium first)
npm run typecheck
```

`v1-reference-kit/` is the source of truth for the stylesheet, the theme
adapter and the skill. `skill/` is generated by the build and committed (git
installs run from the copy, so the built files must be in the repo).

## Layout

```
panel/index.html        one page for panel, page, and file editor
panel/main.js           built IIFE (committed)
src/                    panel sources (TS + two tested .mjs modules)
service/main.cjs        local service: installs the skill
skill/visuals/          generated complete skill (committed)
v1-reference-kit/       stylesheet, adapter, skill source, tests
scripts/build.mjs       the build
test/                   parity, parser, service, browser harness
```

## Updates

Bump `version` in `package.json`, run `npm run build`, commit, push. In
Settings → Extensions choose Update; the next panel open re-syncs the skill.

## Out of scope (v1)

Inline rendering inside chat messages (the SDK has no surface for it),
editing visuals from the panel, image/PDF export, integrations or network
access, VS Code and mobile (extensions do not load there).
